# Lesson 05.01 — Tool Gateway and Permission Boundary

## UNDERSTAND

Design a gateway that mediates tool discovery, validation, policy, approval, execution and audit.

## BUILD

Specify the full path from proposed tool call to validated execution and recorded result.

## BREAK

Attempt an unknown tool, invalid argument, denied scope and approval-required side effect.

## MEASURE

No tool executes unless registration, validation, authorization and required approval all pass.

## SECURE

Tool descriptions are capability metadata, not authorization. Apply least privilege and explicit scopes.

## SHIP

Complete `artifacts/worksheet.md` and retain the artifact manifest as reviewable evidence for this lesson.

## OPERATE

Measure denied calls, approval waits, timeouts, retry counts and tool error rates.

## GOVERN

Review new tools, scope expansions and side-effect changes before production admission.
